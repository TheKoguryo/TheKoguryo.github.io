Compute VM에서 CPU 기반 AI 추론 모델 테스트

CPU 추론은 하드웨어 예산이 제한적이거나, 높은 처리량의 실시간 예측이 필요하지 않은 작은 규모 애플리케이션에서 시도해 볼 수 있는 방법입니다. 문서 검색 및 요약, 고객 지원 챗봇, 엣지 디바이스 분석 등에 시도해 볼 수 있는 방법입니다.

당연히 작은 사이즈 모델을 사용해야 겠지만, 그래도 어느 정도의 성능, 감내할 만한 응답 속도, 동시 접속 유저수 등을 확인하는 작업이 필요해 보입니다. 여기서는 x86기반 CPU에서 제공하는 AVX2/AVX-512와 같은 기술을 이용하여, OCI에서 CPU 기반 AI 추론 성능이 어느 정도 나오는 지를 확인해 보고자 합니다.

테스트할 Compute VM 준비

비교를 위해 OCI에서 8 OCPU, 64 GB 기준, Intel/AMD 기반 CPU를 사용하여 VM을 생성하였습니다.

  1. OS: Oracle Linux 9.8
  2. Shape:
    1. VM.Standard3.Flex으로 시작
    2. 성능 비교를 위해 Intel 최신 CPU(VM.Standard4.Ax.Flex), AMD CPU(VM.Standard.E6.Flex, VM.Standard.E6.Ax.Flex)는 추가로 테스트
    3. 용량: 8 OCPU(16vCPU), 64 GB
      1. m8i.4xlarge, m7i.4xlarge의 16 vCPU, 64 GiB에 맞춘 구성
      2. 테스트 후, 메모리 사용량은 확인후 비용을 고려하여 최적화할 수 있음
  3. Boot Volume: 200 GB
vLLM 설치

vLLM 설치가이드에 따라 설치합니다.

  1. 설치가이드에 따라 Python: 3.10 – 3.13 버전을 설치합니다.

    sudo dnf install python3.12

  2. uv 설치

    curl -LsSf https://astral.sh/uv/install.sh | sh

  3. Python 환경 생성

    uv venv --python 3.12 --seed --managed-python
source .venv/bin/activate

  4. OS 업데이트 및 필요한 컴파일러 g++를 설치합니다.

    sudo dnf update
sudo dnf install -y gcc-c++ numactl-devel
g++ --version

  5. 설치된 glibc 버전이 2.34입니다. vllm 0.29를 설치합니다. 최신버전인 vllm 0.30은 glibc 버전 문제로 설치시 오류가 발생하였습니다.

    $ getconf GNU_LIBC_VERSION
glibc 2.34

  6. 설치

    # use pip
pip install \
  "https://github.com/vllm-project/vllm/releases/download/v0.29.0/vllm-0.29.0+cpu-cp38-abi3-manylinux_2_34_x86_64.whl" \
  --extra-index-url https://download.pytorch.org/whl/cpu

  7. LD_PRELOAD에 Intel OpenMP 추가: sudo find / -iname *libiomp5.so 결과값이 없어, 아래와 같이 수동 설치

    # vLLM을 설치한 동일한 venv를 활성화한 상태에서
pip install intel-openmp

IOMP_PATH=$(find "$VIRTUAL_ENV" -type f -name 'libiomp5.so' -print -quit)
echo "$IOMP_PATH"

export LD_PRELOAD="${IOMP_PATH}${LD_PRELOAD:+:$LD_PRELOAD}"

  8. 설치 확인

    $ vllm --version
WARNING 09-22 06:16:52 [importing.py:45] Triton is installed, but doesn't include CPU backend. Disabling Triton.
INFO 09-22 06:16:52 [importing.py:74] Triton is installed but 0 active driver(s) found (expected 1). Disabling Triton to prevent runtime errors.
INFO 09-22 06:16:52 [importing.py:98] Triton not installed or not compatible; certain GPU-related functions will not be available.
0.29.0+cpu

$ python -c "import vllm, torch; print(vllm.__version__); print(torch.__version__)"
0.29.0
2.13.0+cpu

Advanced Vector Extensions (AVX), Advanced Matrix Extensions (AMX) 지원 여부 및 사용 여부 확인

  1. CPU flag 체크

    lscpu | grep -Ei 'avx512f|avx2|amx'

  2. vllm 서버 로그에서 Worker의 pid를 확인합니다. 예, 82911

    (Worker pid=82911) INFO 09-22 09:03:57 [cpu_worker.py:255] Explicitly set (8.0/62.27) GiB for KV cache on node 0.

  3. 새 터미널에서 다음 명령을 실행합니다.

    sudo perf stat -p <Worker_PID> \
  -e fp_arith_inst_retired.vector,\
fp_arith_inst_retired.256b_packed_single,\
fp_arith_inst_retired.512b_packed_single,\
fp_arith_inst_retired.512b_packed_double \
  -- sleep 30

  4. 새 터미널에서 지속적으로 요청합니다.

    while true; do

      "model": "google/gemma-3-1b-it",
      "messages": [
        {"role": "user", "content": "What is the capital of South Korea?"}
      ]
    }' > /dev/null
done

LLM 서빙 성능 평가

여기서는 vllm 프로젝트에서 제공하는 LLM 성능 평가 도구인 GuildeLLM을 사용하여, 성능을 평가합니다.

  1. GuideLLM을 설치합니다.

    pip install guidellm

  2. 벤치마크를 위해 다음 명령을 실행합니다.

    • max_length=100 조건에 맞춰 token 수를 가정
    • streams로 동시 요청수, 배치 사이즈 지정
    guidellm run \
  --backend kind=openai_http,target=http://localhost:8000 \
  --profile kind=concurrent,streams=1,warmup=5,cooldown=5 \
  --constraint kind=max_duration,seconds=120 \
  --data kind=synthetic_text,prompt_tokens=16,output_tokens=84

  3. 전체 결과 중 일부 항목입니다.

    • 요청에 대한 결과까지 시간(Request Latency), 첫 글자가 보이기까지 시간(TTFT), 이후 생성되는 토큰 간 간격(ITL), 출력 처리량(Output Tokens Per Sec)
    • 전체 응답(Request Latency)까지 5초 걸리며, UI가 스트리밍 모드라면, 첫 응답토큰(TTFT)을 받는 데 0.3초가 걸렸습니다.
    • VM의 고정비용이 나가지만, 일반적인 LLM 서비스에서는 비용 계산시 사용되는 항목으로 보면 Output Tokens Per Sec로 비용을 산정해 볼 수 있습니다.

Open WebUI VM 구성

https://github.com/open-webui/open-webui?tab=readme-ov-file#how-to-install-

  1. public subnet에 Compute VM을 생성합니다.

    • 이름: openwebui
    • OS: Oracle Linux 9
    • Shape: VM.Standard.E4.Flex, 1 OCPU, 16 GB

  2. Docker Engine을 설치합니다.

    sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

sudo dnf install -y docker-ce docker-ce-cli containerd.io

sudo systemctl start docker

sudo usermod -aG docker $USER
newgrp docker

docker run hello-world

  3. vLLM이 호출되는 지 확인합니다. 네트워크에 문제가 없는 지 체크합니다.

    • 예, vLLM VM의 Private IP: 10.0.0.139
    [opc@openwebui ~]$ curl -s http://10.0.0.139:8000/v1/models | jq .data[].id
"google/gemma-3-1b-it"

  4. OPENAI_API_BASE_URL에 vLLM VM의 Private IP로 업데이트하여, Open WebUI 컨테이너를 실행합니다.

    docker run -d \
  -p 3000:8080 \
  -e OPENAI_API_BASE_URL=http://10.0.0.139:8000/v1 \
  -e OPENAI_API_KEY=EMPTY \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

  5. OS 방화벽을 개방합니다.

    # OS 방화벽에서 Open WebUI용 포트, 3000 포트 개방
sudo firewall-cmd --permanent --add-port=3000/tcp
# 방화벽 변경정보 다시 반영
sudo firewall-cmd --reload

  6. 속한 서브넷의 보안 규칙에서 Ingress Rule에 3000 포트를 추가합니다.

  7. 웹브라우저에서 서버로 접속합니다.

    http://{openwebui-VM-Public-IP}:3000

  8. 첫 접속시 화면을 따라 Admin 유저를 생성합니다.

  9. 기본 모델로 google/gemma-3-1b-it가 선택된 상태로 보입니다.

  10. 첫 질문을 하면 아래와 같이 잘 답변합니다. CPU 추론을 사용하는 것과 1b 사이즈 모델임에도 처음 말한 “문서 검색 및 요약, 고객 지원 챗봇, 엣지 디바이스 분석” 용도에 사용할 만한지 질의응답을 통해 확인해 봅니다.
