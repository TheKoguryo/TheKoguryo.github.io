Private AI Services Container 시작하기 - Private Large Language Model Service

Getting Started with Private Large Language Model Service – Part 1를 기반으로 테스트한 내용입니다.

설치할 VM 준비

Install the Private AI Services Container 내용중 Vector Indexing Service을 참조하여 설치합니다.

  1. OCI에서 VM을 생성합니다. 블로그와 달리 현재 기본 선택인 Oracle Linux 9를 사용하였습니다.

    • Name: privateai-cpuvm
    • Shape: VM.Standard3.Flex
    • OS: Oracle Linux 9
    • CPU: 8 OCPU
    • Memory: 64 GB RAM
    • SMT 해제
    • Boot volume: 150GB로 설치

  2. CPU가 AMX, AVX-512를 지원하는지 확인합니다.

    [opc@privateai-cpuvm ~]$ grep -m1 '^flags' /proc/cpuinfo | grep -o 'avx512[^ ]*'
avx512f
...
avx512_bf16
...
Boot Volume Resize

  1. 다음 명령을 실행합니다.

    sudo /usr/libexec/oci-growfs -y
df -h
Podman 설치

  1. Oracle Linux 9 기준 다음 명령으로 설치합니다.

    sudo dnf install -y container-tools

  2. 설치된 버전을 확인합니다.

    podman version

    podman images

    • 실행 예시

  3. 로그아웃 이웃에도 컨테이너가 계속 실행되도록 Lingering 설정

    $ sudo loginctl enable-linger $(whoami)

  4. 컨테이너를 실행후 로그아웃합니다.

    podman run -d ghcr.io/oracle/oraclelinux9-nginx:1.20
exit

  5. VM에 SSH로 재접속하여, 컨테이너가 실행중인지 확인합니다.

    podman ps
Oracle Container Registry (OCR)에서 이미지 다운로드 받기

  1. Oracle Private AI Services Container 이미지는 OCR(Oracle Container Registry)에서 제공합니다. Oracle Account로 로그인합니다.

  2. Access Token이 필요합니다. 없는 경우 오른쪽 상단 유저 정보에서 생성합니다.

  3. 컨테이너 목록에서 Database > private-ai를 선택합니다.

  4. 이미지 다운로드를 위해서 라이센스 동의가 필요합니다. 오른쪽 가운데 Oracle AI Database License 경고문구에서 Continue를 클릭하여 동의합니다.

  5. 로그인후 이미지를 가져오는 것이 되는 지 확인합니다.

    podman login container-registry.oracle.com
docker pull container-registry.oracle.com/database/private-ai:large-cpu-avx512-infer-26.2.2.0.0

  6. 이미지를 확인합니다.

    $ podman images

Private AI Services Container - Private Large Language Model Service 설치하기 - HTTP

  1. 필요한 폴더를 생성합니다.

    cd setup
export PRIVATE_DIR=/home/opc/privateai-cpu-avx512-infer-http
export CONFIG_DIR=/home/opc/config
mkdir -p "$PRIVATE_DIR" "$CONFIG_DIR"

  2. /home/opc/config/config.json 파일을 생성합니다.

    {
  "models": [
    {
      "name": "google/gemma-3-1b-it",
      "path": "google/gemma-3-1b-it",
      "runtime": "vllm",
      "capabilities": ["TEXT_GENERATION"],
      "startup_timeout": 1200,
      "runtime_arguments": [
        "--dtype", "bfloat16",
        "--max-model-len", "4096"
      ]
    }
  ]
}

  3. google/gemma-3-1b-it은 기본 탑재된 모델이 아닙니다. Hugging Face에서 다운로드 받아올 수 있도록, huggingface-token을 이후 실행시 사용할 수 있도록 저장합니다. hf_xxxxx 자리에 사용한 hugging-face-token을 입력하여 생성합니다.

    printf '%s' 'hf_xxxx' > /tmp/huggingface-token
chmod 600 /tmp/huggingface-token

  4. 컨테이너 설정 파일을 생성합니다.

    ./configSetup.sh -d "$PRIVATE_DIR" -c /home/opc/config/config.json

LLM 서빙 성능 평가

여기서는 vllm 프로젝트에서 제공하는 LLM 성능 평가 도구인 GuildeLLM을 사용하여, 성능을 평가합니다.

  1. GuideLLM을 설치합니다.

    pip install guidellm

  2. Hugging Face에서 Read 권한 토큰을 만든 뒤 로그인 합니다.

    hf auth login

  3. 벤치마크를 위해 다음 명령을 실행합니다.

    • max_length=100 조건에 맞춰 token 수를 가정
    • streams로 동시 요청수, 배치 사이즈 지정
    guidellm run \
  --backend kind=openai_http,target=http://localhost:8080 \
  --profile kind=concurrent,streams=1,warmup=5,cooldown=5 \
  --constraint kind=max_duration,seconds=120 \
  --data kind=synthetic_text,prompt_tokens=16,output_tokens=84

  4. 전체 결과 중 일부 항목입니다.

    • 요청에 대한 결과까지 시간(Request Latency), 첫 글자가 보이기까지 시간(TTFT), 이후 생성되는 토큰 간 간격(ITL), 출력 처리량(Output Tokens Per Sec)
    • 전체 응답(Request Latency)까지 5.1초 걸리며, UI가 스트리밍 모드라면, 첫 응답토큰(TTFT)을 받는 데 0.4초가 걸렸습니다.
    • VM의 고정비용이 나가지만, 일반적인 LLM 서비스에서는 비용 계산시 사용되는 항목으로 보면 Output Tokens Per Sec로 비용을 산정해 볼 수 있습니다.

HTTPS 기반으로 설치하기

mkdir -p "$PRIVATE_DIR" "$SECRETS_DIR" "$CONFIG_DIR"

LLM 서빙 성능 평가

여기서는 vllm 프로젝트에서 제공하는 LLM 성능 평가 도구인 GuildeLLM을 사용하여, 성능을 평가합니다.

HTTP 기반 호출할때와 차이는, 기 생성한 Self-Signed 인증서와 API Key를 사용하는 방법의 확인후 기록한 내용입니다.

  1. GuideLLM을 설치합니다.

    pip install guidellm

  2. Hugging Face에서 Read 권한 토큰을 만든 뒤 로그인 합니다.

    hf auth login

  3. 벤치마크를 위해 다음 명령을 실행합니다.

    • max_length=100 조건에 맞춰 token 수를 가정
    • streams로 동시 요청수, 배치 사이즈 지정
    export SECRETS_DIR=/home/opc/secrets
export API_KEY=`cat $SECRETS_DIR/api-key`; echo $API_KEY
export HOST=$(hostname -f); echo $HOST

# 시스템 CA + Private AI 인증서를 합치기
cat /etc/pki/tls/certs/ca-bundle.crt "$SECRETS_DIR/cert.pem" \
  > "$HOME/privateai-ca-bundle.pem"

export SSL_CERT_FILE="$HOME/privateai-ca-bundle.pem"

guidellm run \
  --backend "kind=openai_http,target=https://$HOST:8443,api_key=$API_KEY,verify=true" \
  --profile kind=concurrent,streams=1,warmup=5,cooldown=5 \
  --constraint kind=max_duration,seconds=120 \
  --data kind=synthetic_text,prompt_tokens=16,output_tokens=84


이 글은 개인으로서, 개인의 시간을 할애하여 작성된 글입니다. 글의 내용에 오류가 있을 수 있으며, 글 속의 의견은 개인적인 의견입니다.
