3.3 Autoscaling - Karpenter Provider for OCI (KPO) 사용하기

Cluster Autoscaler를 사용하여 OKE 노드스케일할 수 있습니다. 쿠버네티스 노드스케일을 위해 많이 사용되는 툴로 karpenter가 있습니다. [karpenter-provider-oci]는 OCI를 위한 karpenter 구현체로, OKE 클러스터를 지원합니다. karpenter-provider-oci는 오라클에서 관리하고 있습니다.

OKE 클러스터 준비하기

Karpenter Provider for OCI 설치 요구사항에 맞게 환경을 준비합니다.

  • OKE Cluster (Kubernetes version >= v1.31) 필요

  • OKE Managed Node Pool 또는 Self-Managed Nodes:

    • KPO가 실행될 노드 필요
    • 여기서는 2노드 Node Pool 1개 생성함

  • CNI:

    • OCI VCN IP Native CNI 애드온을 사용하는 경우, 애드온 버전 3.2.0 이상
    • 본 테스트에서는 Flannel CNI로 설치
    • OciIpNativeCNI: NativePodNetworking을 사용하는 경우, 3.0.0 이상이면이 필요하지면, 최신 버전 또는 3.2.0 이상 버전을 사용합니다.

  • Helm client: 설치 필요

  • Enhanced Cluster

OCI IAM Dynamic Group 및 Policy 만들기

  1. Workload Identity를 위한 Dynamic Group을 만듭니다

    • Name: 예, oke-workload-type-dyn-grp

      ALL { resource.type='workload' }

  2. Self-Managed 노드로 추가할 Compute 인스턴스를 포함하는 Dynamic Group을 만듭니다.

    • Name: 예, oke-self-managed-node-dyn-grp

      ALL {instance.compartment.id = '<compartment-ocid>'}

  3. 생성한 Dynamic Group을 위한 Policy를 만듭니다.

    • Name: 예, oke-karpenter-policy

      • <compartment-name>는 원하는 값으로 변경
      • KPO의 기본 기능을 위한 정책입니다. 추가적인 기능을 사용하는 경우 Granting IAM Permissions to Karpenter Provider for OCI 문서를 참조하여 그에 맞는 정책을 추가합니다.
      Allow dynamic-group oke-workload-type-dyn-grp to manage instance-family in compartment <compartment-name> where all {request.principal.namespace = 'karpenter',request.principal.service_account = 'karpenter'}
Allow dynamic-group oke-workload-type-dyn-grp to manage volumes in compartment <compartment-name> where all {request.principal.namespace = 'karpenter',request.principal.service_account = 'karpenter'}
Allow dynamic-group oke-workload-type-dyn-grp to manage volume-attachments in compartment <compartment-name> where all {request.principal.namespace = 'karpenter',request.principal.service_account = 'karpenter'}
Allow dynamic-group oke-workload-type-dyn-grp to manage virtual-network-family in compartment <compartment-name> where all {request.principal.namespace = 'karpenter',request.principal.service_account = 'karpenter'}
Allow dynamic-group oke-workload-type-dyn-grp to inspect compartments in compartment <compartment-name> where all {request.principal.namespace = 'karpenter',request.principal.service_account = 'karpenter'}

    • Name: 예, oke-self-managed-node-policy

      • <compartment-name>는 원하는 값으로 변경
      Allow dynamic-group oke-self-managed-node-dyn-grp to {CLUSTER_JOIN} in compartment <compartment-name>
Karpenter 설치하기

  1. Helm Repo를 추가하고 사용가능한 버전을 확인합니다.

    helm repo add karpenter-provider-oci https://oracle.github.io/karpenter-provider-oci/charts
helm repo update karpenter-provider-oci
helm search repo karpenter-provider-oci/karpenter --versions

  2. 설정 가능한 값을 확인합니다.

    helm show values karpenter-provider-oci/karpenter --version 1.3.0

  3. Helm values 파일을 작성하거나 설치 파라미터로 설정합니다. 여기서는 파라미터로 차트를 설치합니다.

    • compartmentId, vcnCompartmentId, apiserverEndpoint은 각자 환경에 맞게 변경합니다.

      helm install karpenter karpenter-provider-oci/karpenter \
  --version 1.3.0 \
  --namespace karpenter --create-namespace \
  --set "settings.clusterCompartmentId=ocid1.compartment.oc1..aaaaa..." \
  --set "settings.vcnCompartmentId=ocid1.compartment.oc1..aaaaa..." \
  --set "settings.ociVcnIpNative=false" \
  --set "settings.apiserverEndpoint=10.0.0.3" \
  --set "settings.batchMaxDuration=5s" \
  --set "settings.batchIdleDuration=1s"

    • apiserverEndpoint: OKE 클러스터 상세정보에서 Kubernetes API private IPv4 endpoint에서 IP만

    • batchMaxDuration: 연속된 배치시 지정된 시간만큼의 단위로 처리합니다.

    • batchIdleDuration: 배치후 지정된 시간만큼 다음 배치가 없으면, batchMaxDuration에 도달하지 않아도 바로 처리합니다.

  4. 설치를 확인합니다.

    $ kubectl get pods --namespace karpenter
NAME                         READY   STATUS    RESTARTS   AGE
karpenter-584454549b-9xnwx   1/1     Running   0          24s
karpenter-584454549b-jrhn8   1/1     Running   0          24s
Node Pool 만들기

NodePool은 Karpenter가 생성할 수 있는 노드와 해당 노드에서 실행될 수 있는 Pod에 제약 조건을 설정합니다. NodePool은 다음과 같은 작업을 수행하도록 설정할 수 있습니다.

  1. NodeClass 설정

    • Oracle Linux 예제 - kpo-nodeclass-oracle.yaml

      apiVersion: oci.oraclecloud.com/v1beta1
kind: OCINodeClass
metadata:
  name: my-ocinodeclass
spec:
  shapeConfigs:
    - ocpus: 2
      memoryInGbs: 8
  volumeConfig:
    bootVolumeConfig:
      imageConfig:
        imageType: OKEImage
        imageFilter:
          osFilter: "Oracle Linux"
          osVersionFilter: "8"       
  networkConfig:
    primaryVnicConfig:
      subnetConfig:
        subnetId: ocid1.subnet.oc1.ap-seoul-1.aaaaa...
  sshAuthorizedKeys: [ "ssh-rsa AAA..." ]

    • subnetId: Worker Node가 위치할 서브넷 OCID

    • sshAuthorizedKeys: Worker Node에 SSH 접속시 사용할 키의 Public Key 입력

  2. NodePool 설정

    생성될 노드를 정의합니다.

    • 테스트 예제 - kpo-nodepool.yaml

      apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: my-nodepool
spec:
  disruption:
    budgets:
      - nodes: 100%
    consolidateAfter: 1m0s
    consolidationPolicy: WhenEmptyOrUnderutilized
  limits:
    cpu: 64
    memory: 256Gi
  template:
    spec:
      expireAfter: Never
      nodeClassRef:
        group: oci.oraclecloud.com
        kind: OCINodeClass
        name: my-ocinodeclass
      requirements:
        - key: karpenter.sh/capacity-type
          operator: In
          values:
            - on-demand
        - key: oci.oraclecloud.com/instance-shape
          operator: In
          values:
            - VM.Standard.E5.Flex
      terminationGracePeriod: 5m

  3. NodeClass 배포합니다. 배포후 describe 명령으로 이미지 등을 포함한 각 항목이 오류가 없는 지 확인합니다.

    $ kubectl apply -f kpo-nodeclass-oracle.yaml
ocinodeclass.oci.oraclecloud.com/my-ocinodeclass created

$ kubectl get ocinodeclass
NAME              READY   AGE
my-ocinodeclass   True    12s

  4. NodePool을 배포합니다. 배포후 READY=True인지 확인합니다.

    $ kubectl apply -f kpo-nodepool.yaml
nodepool.karpenter.sh/my-nodepool created

$ kubectl get nodepools
NAME          NODECLASS         NODES   READY   AGE

Spot capacity (OCI preemptible) 사용하기

  1. NodePool 설정을 변경합니다.

    • 테스트 예제

      • karpenter.sh/capacity-type만 on-demand에서 spot으로 변경
      • taints 추가
      • instance-shape에 preemptible 자원 할당을 원활하기 위해 다른 shape 추가
      apiVersion: karpenter.sh/v1
kind: NodePool
metadata:
  name: my-nodepool
spec:
  disruption:
    budgets:
      - nodes: 100%
    consolidateAfter: 1m0s
    consolidationPolicy: WhenEmptyOrUnderutilized
  limits:
    cpu: 64
    memory: 256Gi
  template:
    spec:
      expireAfter: Never
      nodeClassRef:
        group: oci.oraclecloud.com
        kind: OCINodeClass
        name: my-ocinodeclass
      requirements:
        - key: karpenter.sh/capacity-type
          operator: In
          values:
            - spot
        - key: oci.oraclecloud.com/instance-shape
          operator: In
          values:
            - VM.Standard.E3.Flex          
            - VM.Standard.E4.Flex
            - VM.Standard.E5.Flex
            - VM.Standard.E6.Flex            
      terminationGracePeriod: 5m
      taints:
        - key: oci.oraclecloud.com/oke-is-preemptible
          effect: NoSchedule
          value: present

  2. NodePool을 다시 배포합니다. 배포후 READY=True인지 확인합니다.

    $ kubectl apply -f kpo-nodepool.yaml

  3. 테스트 배포할 앱의 yaml에 tolerations을 추가합니다.

    # nginx.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
spec:
  selector:
    matchLabels:
      app: nginx
  replicas: 2
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: docker.io/nginx:latest
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 250m
      nodeSelector:
        karpenter.sh/nodepool: my-nodepool
      tolerations:
      - key: oci.oraclecloud.com/oke-is-preemptible
        operator: Exists
        effect: NoSchedule

  3. preBootstrapInitScript로 체크과정을 추가합니다.

    1. 스크립트 준비

      cat > wait-imds.sh <<'EOF'
#!/bin/bash
(
  set -eu

  endpoint="http://169.254.169.254/opc/v2/identity/cert.pem"

  for attempt in {1..30}; do
    code=$(curl --noproxy '*' \
      --connect-timeout 2 --max-time 5 \
      -sS -o /dev/null -w '%{http_code}' \
      -H 'Authorization: Bearer Oracle' \
      "$endpoint") || code="curl-error"

    if [ "$code" = "200" ]; then
      echo "[wait-imds] Instance identity certificate is ready"
      exit 0
    fi

    echo "[wait-imds] attempt=$attempt/30 status=$code"
    if [ "$attempt" -lt 30 ]; then
      sleep 5
    fi
  done

  echo "[wait-imds] ERROR: certificate endpoint did not become ready" >&2
  exit 1
)
EOF

    2. OCINodeClass에 추가

      PRE_BOOTSTRAP_B64=$(base64 < wait-imds.sh | tr -d '\r\n')

  1. Helm Chart 배포시 설정

    Key Description 디폴트
    batchMaxDuration The maximum length of a batch window.
    The longer this is, the more pods we can consider for provisioning
    at one time which usually results in fewer but larger nodes.    		 10s
    batchIdleDuration The maximum amount of time with no new ending pods that
    if exceeded ends the current batching window. If pods arrive faster than this time,
    the batching window will be extended up to the maxDuration.
    If they arrive slower, the pods will be batched separately.    		 1s

  2. karpenter NodePool 배포 설정

    Key Description 디폴트
    disruption.consolidateAfter ConsolidateAfter is the duration the controller will wait
    before attempting to terminate nodes that are underutilized    		 0s
    disruption.budgets.nodes Nodes dictates the maximum number of NodeClaims
    owned by this NodePool that can be terminating at once    		 10%
